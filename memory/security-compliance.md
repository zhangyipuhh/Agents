# 等保三级 · 应用层面合规检查清单

> 本清单依据 **GB/T 22239-2019** 等保三级应用层面要求整理，**不含硬件/物理/网络边界**。其中 **HTTPS 相关项用 🔒 单独标出**，便于集中整改。具体编码实现要求见 [`AGENTS.md`](../AGENTS.md)「等保三级安全编码规范」章节。

---

## 一、身份鉴别

1. **双因素认证**：是否采用口令+短信/令牌/指纹等管理用户登录？管理员/运维账号必须双因素；普通用户建议至少双因素或强口令+验证码。
2. **口令复杂度**：口令复杂度策略是否生效（长度≥8位，含大小写+数字+特殊字符）？前端+后端同时校验，不能只靠前端。
3. **定期更换口令**：是否强制定期更换口令（建议90天内）？系统层面强制，不能仅依赖提示。
4. **登录失败处理**：连续失败≥5次后是否锁定账户（≥30分钟）？需同时防暴力破解和防枚举。
5. **会话超时**：是否设置会话超时自动退出（建议≤30分钟无操作）？敏感系统建议≤15分钟。
6. **鉴别信息传输加密**：用户身份鉴别信息（口令、Token）在传输过程中是否加密？**🔒 必须走 HTTPS，禁止明文传输**。
7. **用户唯一标识**：是否存在共享账号？是否实现用户唯一标识？一人一账号，审计可追溯。

## 二、访问控制

1. **最小权限原则**：是否按最小权限原则分配角色和权限？梳理角色矩阵，删除冗余权限。
2. **权限分离**：是否实现权限分离（如系统管理员、审计管理员、业务操作员分离）？三权分立是等保三级硬性要求。
3. **默认拒绝策略**：默认访问策略是否为默认拒绝所有，仅显式允许必要访问？白名单机制，不能是黑名单。
4. **敏感操作二次授权**：敏感操作（如资金转账、权限变更）是否需二次授权/审批？重要操作需复核或短信确认。
5. **登录限制**：是否限制登录 IP/时间段/设备？建议对管理后台做 IP 白名单。

## 三、安全审计

1. **审计覆盖范围**：是否对所有用户的重要操作（登录、退出、增删改、权限变更）进行审计？覆盖业务操作+系统管理操作。
2. **审计字段完整性**：审计记录是否包含用户ID、时间、IP、操作类型、操作对象、结果？字段缺一不可。
3. **审计留存时间**：审计记录留存时间是否≥6个月？等保三级硬性要求，不可删除。
4. **审计记录保护**：审计记录是否防止非授权删除、修改或覆盖？日志独立存储，仅审计管理员可读。
5. **集中审计分析**：是否具备集中审计分析能力（如 SIEM、日志平台）？能实时告警异常行为。

## 四、入侵防范（输入验证 & 漏洞管理）

1. **输入有效性检验**：是否对所有用户输入进行有效性检验？前端+后端双重校验，白名单优先。
2. **XSS 防护**：是否对输出到页面的数据进行 HTML 编码/转义？使用框架自动转义（React/Vue），或手动编码。
3. **SQL 注入防护**：是否使用参数化查询/预编译语句？禁止字符串拼接 SQL。
4. **命令注入防护**：是否禁止用户输入直接拼接系统命令？使用白名单限制可执行命令。
5. **文件上传漏洞**：是否限制上传文件类型、大小、路径？禁止上传可执行文件；上传目录不可执行。
6. **路径遍历**：是否对用户提供的文件路径做规范化处理？禁止 `../` 等路径跳转。
7. **漏洞扫描和修复**：是否建立漏洞扫描和修复机制，定期扫描并修补已知漏洞？建议每月扫描，高危漏洞≤7天修复。
8. **入侵检测/告警**：是否对重要节点（如数据库、管理后台）部署入侵检测/告警？WAF、HIDS 或应用层监控。

## 五、恶意代码防范

1. **用户提交内容过滤**：是否对用户提交内容进行恶意代码检测？如富文本编辑器需过滤危险标签。
2. **前端资源完整性校验**：前端资源（JS/CSS）是否使用完整性校验（SRI - Subresource Integrity）？防止 CDN 资源被篡改。
3. **第三方组件安全审查**：是否对第三方组件/开源库进行安全审查和版本管理？定期扫描依赖漏洞（如 npm audit）。

## 六、软件容错

1. **统一错误处理**：系统异常时是否提供统一的错误处理页面？禁止直接暴露堆栈跟踪、SQL 语句、服务器路径。
2. **事务回滚机制**：事务失败时是否具备回滚机制？数据库事务一致性保障。
3. **熔断/限流/降级**：高并发/资源耗尽时是否具备熔断/限流/降级机制？防止单点故障拖垮全系统。

## 七、数据完整性

1. **传输完整性**：重要数据在传输过程中是否采用校验技术/密码技术保证完整性？**🔒 TLS 协议自带 MAC 完整性校验**。
2. **存储完整性**：重要数据在存储过程中是否采用校验技术/密码技术保证完整性？如数据库字段签名、文件哈希校验。
3. **完整性监控**：是否对关键配置文件、代码文件做完整性监控？防止被篡改后植入后门。

## 八、数据保密性 🔒

1. **全站 HTTPS**：**🔒 全站是否强制 HTTPS？** 是否存在 HTTP 可访问的入口？**零进度整改项：全站 301 跳转 HTTPS，关闭 80 端口或强制跳转**。
2. **敏感数据传输加密**：**🔒 敏感数据（口令、身份证、银行卡号）传输是否全部走 HTTPS？** 登录、支付、个人中心等接口必须 HTTPS。
3. **混合内容排查**：**🔒 是否存在混合内容（Mixed Content）？** 页面内是否有 HTTP 资源？检查图片、JS、CSS、API 接口、iframe 是否全 HTTPS。
4. **HSTS**：**🔒 是否开启 HSTS（HTTP Strict Transport Security）？** 防止 SSL 剥离攻击；建议 max-age≥31536000。
5. **TLS 版本与加密套件**：**🔒 TLS 版本和加密套件是否符合要求？** **禁用 SSLv2/v3、TLS 1.0/1.1；禁用 RC4、DES、MD5、SHA1；启用 TLS 1.2/1.3**。
6. **受信任 CA 证书**：**🔒 是否使用受信任 CA 签发的证书？** 证书是否有效未过期？自签名证书测评可能不通过；需配置完整证书链。
7. **敏感数据存储加密**：敏感数据在存储过程中是否加密（数据库、日志、备份）？如密码用 bcrypt/Argon2；身份证等用 AES 加密存储。
8. **密钥安全存储**：加密密钥是否安全存储，与数据分离？密钥放 KMS/HSM，禁止硬编码在代码中。

## 九、数据备份恢复

1. **本地备份**：是否对重要数据进行本地备份？定期自动备份。
2. **异地备份**：是否对重要数据进行异地备份？防止单点灾难。
3. **恢复演练**：是否定期演练恢复？备份数据是否可成功还原？建议每半年至少一次。
4. **高可用/热备**：关键系统是否具备高可用/热备能力？RTO/RPO 需满足业务要求。

## 十、剩余信息保护

1. **客户端会话清理**：用户退出后，浏览器端是否清除会话标识（Cookie/Token）？设置 Cookie 过期，清理 localStorage。
2. **服务端会话失效**：服务器端会话是否及时失效？服务端维护会话黑名单或短时效 Token。
3. **内存/缓存清理**：内存/缓存释放时，是否清除残留敏感数据？如密码框内容、临时解密数据。

## 十一、个人信息保护

1. **最小必要原则**：是否仅采集业务必需的个人信息？遵循最小必要原则。
2. **授权同意**：采集个人信息前是否获得用户授权同意？需有明确同意机制，不能默认勾选。
3. **禁止对外提供**：未经授权是否禁止对外提供个人信息？包括第三方接口、日志、测试环境。
4. **用户权利保障**：是否支持用户查询、更正、删除其个人信息？满足《个人信息保护法》要求。

## 🔒 HTTPS 零进度 · 快速启动清单

若 HTTPS 尚未部署，建议按以下顺序推进：

| 步骤 | 任务 | 预计耗时 |
|:---:|:---|:---:|
| **1** | 购买/申请受信任 CA 证书（Let's Encrypt/阿里云/腾讯云等） | 1 天 |
| **2** | 服务器（Nginx/Apache/网关）配置证书，启用 443 端口 | 1-2 天 |
| **3** | 配置 HTTP 80 端口 **301 永久跳转**到 HTTPS | 2 小时 |
| **4** | 全站扫描**混合内容**（HTTP 图片/JS/CSS/API），全部替换为 HTTPS | 2-5 天 |
| **5** | 配置 **HSTS** 响应头 | 30 分钟 |
| **6** | 使用工具（SSL Labs / 腾讯云 SSL 检测）扫描 TLS 版本和加密套件，**禁用弱协议/算法** | 2 小时 |
| **7** | 验证证书链完整性、过期时间，配置自动续期 | 2 小时 |
| **8** | 回归测试：所有页面、接口、支付流程在 HTTPS 下正常 | 2-3 天 |
